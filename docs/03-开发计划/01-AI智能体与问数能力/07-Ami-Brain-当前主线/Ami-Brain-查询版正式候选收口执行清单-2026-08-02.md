# Ami Brain 查询版正式候选收口执行清单

> 日期：2026-08-02
> 目标：把当前“代码与自动门禁基本完成”推进为“同一真实候选具备受控试运行资格”。
> 产品画像：`query_only_v1`
> 最终准入条件：八类 evidence receipt 全部通过、未过期且绑定同一 `candidateId`，`brain:release:candidate close` 输出 `releaseEligible=true`。

## 1. 第一性原理边界

试运行不是“代码能构建”或“测试全绿”，而是要同时证明五件事：

1. 候选不可变：代码、Release、模型、数据快照、题集和部署身份不能在验收中途漂移。
2. 查询安全：三端、`super_admin` 加七个活跃 Brain 角色和历史消息都不能绕过查询版边界产生业务写入。
3. 结果可用：100 Gold、固定 60 题和真实用户旅程证明答案、口径、性能与失败状态可接受。
4. 环境真实：目标数据库、真实账号、真实网络、真实 provider 和真实部署均参与验收。
5. 可控退出：监控能发现风险，灰度能暂停，回滚能恢复 baseline，且回滚后 Action 仍关闭。

任意一项缺失都保持 No-Go；不得用历史 Release、diagnostic 报告、其他 commit 或其他数据快照拼接补齐。

## 5. 八类同候选证据

下述 `<LOCK>` 均指正式 `candidate-lock.json`。所有 artifact 必须位于仓库内；receipt 会读取真实文件字节并记录 SHA-256，文件缺失、被篡改或通过 symlink 逃出仓库都会阻断 close。receipt v2 同时绑定有效期、reviewer、trace 和 review context，单项证据最长有效 168 小时；最终 eligibility 以八项证据中最早到期时间为准。

### 5.1 `release_contract`

```bash
npm run brain:release:acceptance -- \
  --release-id=<RELEASE_ID> \
  --runtime-commit=<RUNTIME_COMMIT> \
  --production-health-url=<READY_URL> \
  --store-id=<STORE_ID> \
  --run-key=<ACCEPTANCE_RUN_KEY>

npm run brain:release:candidate -- receipt \
  --candidate-lock=<LOCK> \
  --evidence-type=release_contract \
  --status=passed \
  --artifact=outputs/ami-brain-release-acceptance/<ACCEPTANCE_RUN_KEY>/acceptance-evidence.json \
  --expires-in-hours=168
```

## 6. 最终关闭与 Go/No-Go

```bash
npm run brain:release:candidate -- close \
  --candidate-lock=<LOCK> \
  --evidence-dir=outputs/ami-brain-release-candidates/<CANDIDATE_ID>/evidence
```

必须同时满足：

- [ ] 输出 `releaseEligible=true` 且 blockers 为空。
- [ ] 八类 receipt 全部 `passed`、未过期、artifact 当前 SHA-256 一致。
- [ ] candidateId、commit、Release、fingerprint、provider/model、数据快照、题集、部署和门店均未漂移。
- [ ] 产品、QA、运维完成 Go/No-Go 签字。
- [ ] 试运行范围锁定为 1 店、5—10 人、7 天、查询版、Action 双关闭。

若任一身份变化或修复导致代码、Release、模型、数据快照、题集、部署变化，原 candidate 作废，必须重新生成 candidate lock 和八类证据。

## 7. 试运行观察与停止线

每一级灰度至少观察：成功率、事实错误/口径错误、P95/P99、澄清率、provider unavailable、权限拒绝、跨店风险、假成功、长期 running 和用户放弃率。

立即暂停或回滚的停止线：

- 任意跨店泄漏、越权、业务写入或假成功。
- candidate/Release/provider/model 身份无法追溯。
- 失败被三端显示为成功，或出现无法终止的 running。
- 性能连续超阈值且无可验证降级。
- 回滚不可执行，或回滚后 Action 开关不再关闭。
