# Ami Ask 独立语义路由层实施计划

## 1. 目标

在 Ami Ask 自由 SQL 链路前增加独立语义路由层，先确定指标、维度、答案形态、时间与必要澄清，再把已授权的少量候选视图交给 SQL 模型。

目标指标：

- 286 题候选视图召回率不低于 95%。
- 目标视图命中率不低于 75%。
- 无理由澄清率不高于 8%。
- 真实歧义澄清保留率 100%。
- 确定性路由 P95 小于 50ms。
- 低置信度语义模型回退占比不高于 20%。

## 2. 独立性与安全边界

- 新实现仅位于 `ask-data-free-sql` 模块。
- 不导入 Ami Brain Runtime、Ontology、Release、Registry、Capability 或评测体系。
- 不读取 `business_definition`、`business_definition_projection`。
- 不改变权限过滤、单门店注入、SQL Guard、成本门禁、只读事务、敏感字段和 LIMIT。
- 关闭 `ASK_DATA_SEMANTIC_ROUTER_ENABLED` 后恢复原候选选择器。

## 3. 实现内容

### 3.1 语义合同

为 34 个视图分别声明唯一指标 Key、中文名称、同义表达、句式模式、首选视图、允许维度和答案形态。

重点固定以下口径：

- 营业额、订单收入：订单经营收入。
- 日结、收银汇总、结账金额：日结净收。
- 实收流水、支付记录、退款流水：支付退款明细。
- 产品订单、商品销量：商品销售。
- 项目销量、最受欢迎项目：项目服务销售。
- 各供应商采购金额：供应商表现。
- 采购单、采购明细：采购明细。
- ROI、获客成本、投产：营销 ROI。

### 3.2 确定性解析

按答案形态、指标、维度、时间、实体、筛选条件的顺序解析。唯一匹配返回 1—2 个候选，组合问题最多 4 个，低置信度池最多 8 个。

默认口径：

- “最近”按近 30 天。
- 排行未指定数量时返回前 10。
- 趋势 30 天内按日，更长范围按月。
- “当前”按最新可用数据。

### 3.3 澄清策略

仅在缺失条件会实质改变结果时澄清：

- 节日、营销节点未指定年份。
- “大额”等阈值没有金额定义。
- 名称无法唯一定位。
- 指标冲突且没有比较关系。

### 3.4 低置信度模型

只在无确定性指标、指标冲突或置信度低于阈值时调用一次结构化语义模型。模型只能从权限过滤后的指标和候选视图中选择，不能生成 SQL、扩大候选或新增指标。失败时保留安全确定性候选；完全没有安全候选时返回针对性澄清。

### 3.5 链路与审计

查询链路调整为：

```text
权限过滤 → 语义解析 → 候选路由 → 必要澄清/模型回退
→ SQL 生成 → Guard/成本门禁 → 只读执行 → 回答组织 → 审计
```

`queryPlan.semanticIntent` 返回可选的意图、答案形态、指标、维度、置信度、路由模式和假设。审计复用 `queryMetaJson` 保存确定性候选、最终候选、耗时、回退原因和澄清原因。

## 4. 开关与回滚

```dotenv
ASK_DATA_SEMANTIC_ROUTER_ENABLED=false
ASK_DATA_SEMANTIC_ROUTER_SHADOW=true
ASK_DATA_SEMANTIC_ROUTER_MODEL_FALLBACK=true
ASK_DATA_SEMANTIC_ROUTER_MIN_CONFIDENCE=0.75
```

- Shadow 模式只记录新旧候选差异，实际 SQL 仍使用旧选择器。
- 开启后使用语义候选和语义完整性策略。
- 关闭后立即恢复旧选择器，不删除合同和历史审计。

## 5. 验收

- 34 个视图均有唯一语义入口，指标 Key、别名和视图引用通过合同检查。
- 订单、日结、支付、商品、项目、供应商、营销等重叠指标按治理口径路由。
- 节日无年份和大额无阈值保留澄清。
- 未授权指标在模型调用前拒绝。
- 模型失败、非法视图和越权候选安全回退。
- 复跑 286 题候选 Shadow 对比，并分别报告候选召回、模型回退比例、路由耗时。
- 真实 SQL 与最终回答准确率必须另行执行真实模型、数据库和回答闭环，不用离线候选结果代替。
