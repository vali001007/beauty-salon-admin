# Ami Ask 34 视图问题集实测报告

- 测试日期：2026-08-02
- 源题库：`Ami-Brain-全领域实测问题集-2000.csv`，共 2000 题
- 运行环境：`development_admin`，门店 ID 6
- 模型：`openai_responses/gpt-5.6-terra`

## 一、结论

**当前结果不能作为“34 个视图每个不少于 10 题并通过”的验收结论。**

原题库只有 25/34 个视图能严格选满 10 道与视图字段相符的只读查询题；最终实测 286 道题，题号全局不重复，距离 340 题要求缺 54 题。若强行补足，只能通过重复问题或把不相关问题错配给视图，会制造虚假准确率。

复跑瞬时失败后，严格链路准确率为 **56.3%（161/286）**；链路通过率为 **71.7%**；预期视图命中率为 **56.3%**。平均耗时 **12.7 秒**，P50 **13.5 秒**，P95 **21.9 秒**。

满足 10 题且 10/10 通过的视图有 5 个：商品库存、预约、营销活动、已确认实际利润、营销 ROI。满足 10 题但 0/10 的视图有 2 个：项目服务销售、项目目录。

本次使用开发管理员数据库连接，只证明开发环境真实执行，不代表生产专用只读角色已经通过最小权限验收。

## 二、指标口径

- 严格准确率：预期视图命中、Guard/数据库执行成功、回答数字可由结果或时间范围支撑，三项同时满足才算通过。
- 链路通过率：SQL 和回答可以完成且数字有依据，即使选中了另一个可回答的重叠视图也可通过。
- 预期视图命中率：用于判断当前 Catalog、关键词候选和模型路由能否把问题送到目标视图。
- 选题唯一性：同一道源题只能分配给一个视图；语义重叠题通过全局匹配分配，不重复计入多个视图。
- 无数据率：仅统计 SQL 返回 0 行；聚合 SQL 返回 1 行但值为空时不会计入，因此只能作为物理空结果参考。
- 题库没有 expected SQL/expected result，本报告不能把“回答有依据”进一步宣称为最终业务语义完全正确。

## 六、答错原因

| 原因 | 次数 | 产品含义 |
|---|---:|---|
| clarification | 73 | 问题本可由现有字段回答，但模型要求补充信息；主要影响直接可用性。 |
| candidate_selector_miss | 26 | 目标视图未进入候选集合，后续模型不可能选中。 |
| model_view_selection_miss | 18 | 目标视图已进入候选，但模型选了语义重叠的其他视图。 |
| guard_view_join_not_allowed | 4 | 题目需要跨视图组合，当前安全策略禁止 Join。 |
| guard_time_range_exceeded | 2 | 查询超过 730 天或时间范围解析无效。 |
| guard_field_not_allowed | 1 | 模型生成了目录未登记字段或错误 SQL 结构。 |
| guard_source_view_not_allowed | 1 | 模型使用了未登记视图或错误来源。 |

最主要的问题不是数据库不可读，而是从自然语言到语义视图之间的路由：大量清晰问题被过度澄清，或目标视图没有进入最多 8 个候选视图。重叠指标缺少唯一的数据归属，也使模型在订单/日结、采购/供应商、营销转化/ROI 之间摇摆。

## 七、建议修复顺序

1. P0：修复轻量候选选择器。补齐项目价格/时长/类型、项目销量、经营成本、财务对账、客户价值分层、营销归因与 ROI 等同义词，并为明确问题禁止无理由澄清。
2. P0：建立指标归属优先级。例如订单营业额、日结收入、支付实收分别明确默认视图；供应商金额优先汇总视图还是采购明细视图也必须固定。
3. P1：对合理的跨域问题建设组合语义视图，而不是放开任意 Join。优先处理“客户余额 + 次卡资产”“卡项 + 预约”“对账运行 + 订单支付”三类高频问题。
4. P1：降低回答阶段回退率。当前较多回答因生成了结果外数字而回退为确定性摘要，虽然安全，但用户体验偏机械。
5. P1：补齐 54 道 Ask 专用题后，再执行真正的 34×10 验收；本报告中的不足样本视图只能作为探索性结果。
6. P2：完成生产专用只读角色的 34 视图授权、真实权限矩阵和浏览器验收后，才能宣称生产可用。

## 九、独立语义路由 Shadow 复测

针对本报告暴露的候选缺失和过度澄清问题，Ami Ask 已增加独立语义路由层。该层不接入 Ami Brain 运行时，只使用 Ask 自己的 34 视图指标合同和句式模式。

在相同 286 道全局不重复问题上执行确定性 Shadow 对比：

| 指标 | 原选择器 | 新语义路由 |
|---|---:|---:|
| 候选视图召回率 | 73.4% | 100.0% |
| 召回提升 | - | +26.6 个百分点 |
| 平均候选视图数 | 最多 8 个 | 1.09 个 |
| 预计需要模型回退 | 未统计 | 2.5% |
| 确定性路由平均耗时 | 未统计 | 约 0.6ms |
| 确定性路由 P95 | 未统计 | 小于 1ms |
| 无理由澄清 | 原模型发生 73 次 | 规则层 0 次 |

真实歧义规则识别出 31 题，占 10.8%，包括节日/活动未指定年份和“大额退款”未指定金额阈值。这些问题仍应澄清，不能为了提高表面通过率自动猜测。

本次 Shadow 不调用 SQL 生成模型、不执行数据库，也不调用回答模型。因此：

- 可以确认候选召回率和路由耗时已达到门禁。
- 不能据此修改原报告的 56.3% 严格链路准确率。
- 目标视图最终命中率、SQL 执行成功率和最终回答准确率，需要启用语义路由后重新运行真实 286 题闭环。
